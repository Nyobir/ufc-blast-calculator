# Розрахунковий шлях UFC Blast Wave Calculator

Це опис **поточної реалізації**, а не повної заміни UFC 3-340-02. Код
розраховує додатну фазу навантаження для сферичного повітряного або
напівсферичного наземного вибуху. Основний шлях просторового розрахунку —
`compute_facade()` у `ufc_blast/core/blast_params.py`; CLI та GUI викликають
його, щоб не дублювати алгоритм. Окремий `compute_point()`/CLI `point`
розраховує **звичайне відбиття** в одній заданій точці й не виконує корекцію
фасаду для області Маха.

## 1. Вхід і геометрія

Параметри: тротиловий еквівалент `W` (кг), перпендикулярна відстань
`R` (м), висота заряду `Hc` над землею (м), а для фасаду також `width`,
`height` і крок `step` (м). Для плаского фасаду `geometry.generate_grid()`
будує точки `(dx, dy)`. **Нульова вертикальна координата відповідає висоті
заряду**, а земля має `dy = -Hc`; висота фасаду від землі сягає
`dy = height - Hc`. Для кожної точки:

```text
R_alpha = sqrt(R^2 + dx^2 + dy^2)
alpha   = arccos(R/R_alpha)
Z       = R_alpha/W^(1/3)
```

`alpha` — кут падіння відносно нормалі до стіни, `Z` — приведена відстань
(м/кг^(1/3)). Модель вибирає родину графіків за
`Hc/W^(1/3) > 0.397` (повітряний вибух), інакше — наземний. Це **правило
вибору графіка**, не фізична точка розриву навантаження. Для значень
`0.3–0.5` код попереджає про чутливість до цього вибору; обидві родини
слід порівнювати, а не вважати їх однаковими.

## 2. Початкові параметри хвилі

`compute_points_batch()` обробляє сітку масивами NumPy. Для повітряного
вибуху початкові `Ps0`, `tA`, `t0` беруться з даних рис. 2-7; для наземного
— з рис. 2-15. Відбиття на фасаді дають спільні таблиці рис. 2-193 і
2-194:

```text
Pr_alpha = C_alpha(Ps0, alpha) * Ps0
ir_alpha = ir_alpha_scaled(Ps0, alpha) * W^(1/3) / 1000
```

`Pr_alpha` та `Ps0` мають одиниці кПа; **всередині коду** імпульс
`ir_alpha` має кПа·с, часи `tA` і `t0` — секунди. Значення графіків
у кПа·мс/кг^(1/3) і мс/кг^(1/3) переводяться множенням на
`W^(1/3)/1000`. CLI показує імпульс також у кПа·мс, а часи — у мс.

Позитивні одновимірні залежності інтерполюють у log–log шкалі.
У двовимірних таблицях інтерполяція лінійна за кутом у межах кривої та
логарифмічна між додатними родинами тиску. За межами даних програма
**притискає до межі й ставить прапорець**, а не видає непозначене
позадіапазонне значення. `C_alpha` не зобов'язаний спадати монотонно з
кутом: у зоні переходу типу відбиття можливий локальний максимум.

## 3. Додатна фаза й параметр Фрідландера

```text
tau = (t - tA)/t0
P(t) = Pr_alpha*(1 - tau)*exp(-b*tau),   tA <= t <= tA + t0
ir_alpha = Pr_alpha*t0/b^2 * (b - 1 + exp(-b))
```

`b` добирають так, щоб інтеграл відтворював **відбитий**, а не падаючий
імпульс. Для однієї точки `solve_friedlander_b()` використовує метод
Брента в межах `0.01–50`; для сітки — векторизовані обмежені ітерації
Ньютона. Якщо корінь не існує в цих межах, повертається межове значення
й ставиться `friedlander_b` (скалярний шлях також попереджає). Це не
«точно узгоджена» крива без застережень.

## 4. Область Маха — лише повітряний вибух

Після звичайного batch-розрахунку `apply_mach_stem()` визначає для кожного
стовпця висоту потрійної точки `HT` з рис. 2-13. Межа на фасаді має
координату `mach_dy = HT - Hc`. **Рис. 2-13 задає лише межу області**, а
не місце відбору параметрів хвилі. Нижче неї застосовується процедура
`compute_mach_front()` за UFC §2-13.2:

1. Знаходимо відстань до точки на землі перед стовпцем
   `Rg = sqrt(R^2 + dx^2)` і кут початкової хвилі
   `alpha_g = atan2(Rg, Hc)`.
2. З електронних даних рис. 2-9/2-10 беремо наземні відбиті тиск та
   питомий імпульс. Вони стають падаючими параметрами фронту Маха.
3. За відповідними тиском та імпульсом інвертуємо криві рис. 2-7,
   отримуємо приведені відстані й визначаємо `tA` та `t0`.
4. Фронт рухається горизонтально, тому кут до стіни для стовпця —
   `theta = atan2(abs(dx), R)`. За рис. 2-193/2-194 визначаємо відбиті
   на стіні тиск та імпульс. В ідеалізованій моделі значення в цьому
   стовпці **рівномірні за висотою** нижче межі Маха.

Якщо `ir_alpha >= Pr_alpha*t0/2`, початкова тривалість з графіка не може
вмістити цей імпульс у кривій із додатним спадом. UFC вводить фіктивну
трикутну тривалість `t_rf = 2*ir_alpha/Pr_alpha`; реалізація використовує
`t0 = 1.005*t_rf` для скінченного `b` і ставить інформаційний прапорець
`t0_fictitious`. Це не точний трикутник UFC і не збереження вихідного
`t0`. Притискання графіків у процедурах Маха отримує окремі прапорці
(`triple_point`, `mach_ground`, `mach_inverse` та відповідні таблиці).
Позначені ними випадки не можна називати прогнозом **у межах графіків**.

## 5. Чому `point` і центр фасаду різняться

Для `W=200 кг`, `R=30 м`, `Hc=5 м`:

- `ufc-blast point --W 200 --R 30 --Hc 5 --alpha 0` дає звичайне
  відбиття: `Pr_alpha = 64.864 кПа`, `ir_alpha = 0.468400 кПа·с`.
- `compute_facade(R=30, W=200, Hc=5, width=20, height=10, step=0.25)`
  створює **3321 точки**. Центр `(dx=0, dy=0)` лежить нижче межі Маха,
  тому результат після корекції: `Pr_alpha ≈ 110.081271 кПа`,
  `ir_alpha ≈ 0.622702163 кПа·с`. Для цього прикладу немає прапорців
  меж графіків.

Це не два вимірювання однієї формули: CLI `point` не запускає корекцію
фасаду. Додатну фазу GUI показує контуром і часовою кривою. Модель не
розраховує від'ємну фазу, деформації стіни чи безпеку споруди.
